# Week 3 data — Predictive Modeling on Encoded Text

Two corpora serve two jobs this week. The **lecture** uses 20 Newsgroups,
fetched at runtime (below). The **assignment and practice assignment** use the
vendored **Northwind Outfitters support-ticket corpus** — three CSVs in this
folder, documented first because they are what most students come here for.

## Vendored — the Northwind support-ticket corpus

| File | Rows | Columns | Used by |
|---|---:|---|---|
| `tickets.csv` | 3,000 | `ticket_id`, `channel`, `subject`, `body`, `queue` | the graded assignment |
| `incoming_batch.csv` | 400 | `ticket_id`, `channel`, `subject`, `body` — **no label** | the graded assignment's ship-it task |
| `practice_tickets.csv` | 900 | same as `tickets.csv` | the practice assignment |

**Source & licence:** written for this course — fully synthetic, generated by a
deterministic script in the instructor repository (`tools/make_week03_tickets.py`);
no third-party content, CC0. No real customers, products, or order numbers.

**Labels.** `queue` is one of `shipping`, `returns-warranty`, `billing`,
`account-access`, `product-question` (the practice corpus uses only the first,
third, and fourth). Class shares are deliberately unequal.

**The corpus is deliberately messy, the way an inbox is.** Facts you will
rediscover in the assignment, stated here so nobody mistakes them for bugs:

- Some tickets carry **two intents** ("the zipper broke *and* I was charged
  twice"). The label follows the **first-stated, dominant intent** — that is
  the routing rule Northwind's human dispatchers were instructed to apply, and
  the labels are consistent with it.
- ~1 in 4 tickets contains **typos**; `chat` tickets are short and informal.
- A few tickets are **junk** ("see attached screenshot…", a bare order
  number) that barely vectorize at all.
- Some tickets are **exact resubmissions** of an earlier ticket. Handle them
  before you split, or your test set contains rows your model memorized.
- The `channel` column is context, not text — whether to use it is your call.

`incoming_batch.csv` has no `queue` column anywhere public: it is the batch
your finished router must route. The labels exist only in the instructor
repository, for marking.

## Fetched at runtime — do not look for these files here

| Dataset | Where it comes from | Size | Used by | Licence |
|---|---|---|---|---|
| **20 Newsgroups** (4 groups: `alt.atheism`, `comp.graphics`, `sci.med`, `soc.religion.christian`) | `sklearn.datasets.fetch_20newsgroups(...)` — downloads once to `~/scikit_learn_data/`, cached thereafter | ~14 MB compressed for the full archive; the 4-group slice is 2,257 train / 1,502 test posts | `lecture-notebook.ipynb` §0.3 onward, and `Week03.jsx` | Public and redistributable; originally collected by Ken Lang. See the [sklearn dataset page](https://scikit-learn.org/stable/datasets/real_world.html#newsgroups-dataset). |

**The lecture deck and the lecture notebook use the same slice, the same
`remove=` argument, and the same vectorizer configuration**
(`TfidfVectorizer(stop_words="english", min_df=2, sublinear_tf=True)`), so every
figure on a slide reproduces in the notebook. Changing any of the three breaks
that correspondence.

Two things about the way Week 3 calls it are load-bearing and are *not*
cosmetic defaults:

- **`remove=("headers", "footers", "quotes")`.** The raw posts carry `From:`,
  `Organization:` and signature lines that identify the newsgroup directly. A
  classifier trained without this argument reaches the high nineties by
  learning email domains, which is the standard dishonest way this benchmark
  gets reported.
- **The four groups are chosen, not arbitrary.** `comp.graphics` and `sci.med`
  separate cleanly from everything. `alt.atheism` and `soc.religion.christian`
  are the notoriously confusable pair — the same subject matter from opposite
  positions — and `alt.atheism` is also the smallest group (480 train / 319
  test). That pair is what gives §5.2's macro-vs-micro argument something real
  to bite on, and it is the subject of the §5.8 error analysis: the model's
  dominant failure is atheism posts that quote scripture in order to argue
  against it. `sci.med` is the class §5.4 subsamples into a genuinely
  imbalanced binary task.

**The empty documents are deliberate.** With `remove=` plus
`stop_words="english"` and `min_df=2`, **54 training and 46 test posts** end up
with an all-zero TF-IDF row. 41 of the 46 were nothing but a quoted reply and a
signature; the rest lost every remaining word to the stopword list or to
`min_df=2`.

The notebook does **not** filter them out. §5.7 has students discover them
through error analysis — first as 46 documents sharing one byte-identical
`predict_proba` row, then as the explanation for the collapse of Euclidean kNN
in §2.4 (0.2417 with them, 0.8089 without). Any rewrite of this week's material
that "cleans the data first" destroys the planted teaching moment.

**Nothing in Week 3 requires an API key or network access after the first
`fetch_20newsgroups` call.**

### `glove_20news_100d.npz` — pretrained word vectors

**Source:** GloVe 6B (Wikipedia 2014 + Gigaword 5), 100-dimensional, obtained
via `gensim.downloader.load("glove-wiki-gigaword-100")`.
Original release: <https://nlp.stanford.edu/projects/glove/> (Pennington,
Socher & Manning, EMNLP 2014).
**Licence:** Public Domain Dedication and Licence (PDDL) v1.0 —
<http://opendatacommons.org/licenses/pddl/> — which permits redistributing a
derived subset.
**Used by:** `lecture-notebook.ipynb` §4.2, which represents each document as
the average of its word vectors and compares that against TF-IDF.

Two arrays:

- `words` — `(19696,)` object array, ordered by frequency in this week's
  corpus, most frequent first.
- `vectors` — `(19696, 100)` `float32`; row *i* is the vector for `words[i]`.

**Why a subset rather than the full release.** The full model is 400,000 words
and a 128 MB download — too slow to watch in class and a hard network
dependency for a five-minute demo. The subset keeps every word that occurs at
least **twice** in the Week 3 corpus (train + test, `CountVectorizer` defaults)
**and** exists in GloVe's vocabulary: 19,696 words, which is 51.6% of the
corpus's distinct tokens but **96.7% of its token occurrences**. The notebook
measures and prints that coverage on the training set rather than taking this
file's word for it.

**Why not reuse Week 2's `glove_6b_100d_subset.npz`.** That file is built
around Week 2's help-centre corpus plus GloVe's global top 15,000, and covers
88.8% of this week's tokens against this subset's 96.7%. The averaged-embedding comparison in §4.2 is a
head-to-head against TF-IDF, so it should not be handicapped by a vocabulary
gap that has nothing to do with the representation being tested.

To regenerate (needs network access on first run; downloads the full model to
`~/gensim-data/` and is offline thereafter):

```bash
uv run python week-03-text-classification/data/make_glove_subset.py
```

The generator is fully deterministic — no RNG anywhere — so re-running it
reproduces the file.

## Loading these files in a notebook

Week 3 notebooks resolve data **local first, URL fallback**, so they work in a
fresh clone and in a Colab tab with nothing checked out:

```python
DATA_URL = ("https://raw.githubusercontent.com/prof-tcsmith/6564F26-DATA/main/"
            "week-03-text-classification/data/")
CANDIDATES = [Path("data"), Path("week-03-text-classification/data"), Path("../data")]

def data_path(name: str) -> str:
    for base in CANDIDATES:
        if (base / name).exists():
            return str(base / name)
    return DATA_URL + name
```
