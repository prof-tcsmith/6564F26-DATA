## `reviews.csv` — Northwind product reviews (Assignment 4)

| Field | Value |
| --- | --- |
| **Rows** | 4,837 — split in advance into 3,164 train / 469 validation / 1,204 test |
| **Columns** | `id`, `split`, `slice`, `label` (1 = positive, 0 = negative), `text` |
| **Source** | Generated by `make_reviews.py` (in this folder). Synthetic; no real customer data. |
| **Text** | Lower-case, no punctuation, 5–49 words (median 20). No review appears twice. |

Every review carries a `slice` tag saying which kind of word order decides its
label. That column is what lets you break a model's accuracy out by failure
mode instead of averaging everything into one number:

| `slice` | What it looks like | Test rows |
| --- | --- | ---: |
| `simple` | One opinion, no tricks: *"the battery easily lasts two days"* | 273 |
| `contrast` | *"A **but** B"* — the label follows **B**. Every review appears in both orders, with opposite labels. | 296 |
| `scope_short` | A frame that may contain **not** (*"it is not true that…"*), then the opinion a few words later | 336 |
| `scope_long` | The same, with 15–20 filler words between the *not* and the opinion | 299 |

**Why `contrast` is exactly 50% for a bag of words.** The two orderings of a
`contrast` review contain exactly the same words, so a bag-of-words model sees
two identical rows — and gives both the same answer. One of the pair is always
wrong, so it scores exactly 0.500 on that slice. That is a proof, not a
measurement.

Measured on the test split, `TfidfVectorizer()` (default settings) +
`LogisticRegression(max_iter=2000)`:

| Features | Overall | `simple` | `contrast` | `scope_short` | `scope_long` |
| --- | ---: | ---: | ---: | ---: | ---: |
| single words | 0.6453 | 1.0000 | **0.5000** | 0.5327 | 0.5920 |
| single words + word pairs | 0.7533 | 1.0000 | 0.9291 | 0.5357 | 0.5987 |

Word pairs rescue `contrast` (the word *but* sits right beside the clause that
decides the label) but not the `scope` slices, where the deciding words are too
far apart for any word pair to hold both.

**Do not re-split the data.** The two orderings of each `contrast` review must
stay in the same split, or the 0.500 result above stops being exact. The
assignment notebook uses the `split` column as shipped.

**Honest limitations.** The reviews are built from templates, so a model that
learns the templates can score near 1.000 — real reviews are messier, and the
number worth reading here is the *gap* between model types, not the absolute
level. Every word in the test split also appears in training, so this corpus
tests how models handle *word order*, not unfamiliar vocabulary. And real
customers express contrast and negation in far more ways than *but* and *not*.

Deterministic given `SEED = 6564`; rebuild with
`uv run python week-04-sequence-models/data/make_reviews.py`.

## `dates_train.csv` / `dates_test.csv` — date normalisation (lecture §6)

| Field | Value |
| --- | --- |
| **Rows** | 6,000 train / 1,000 test |
| **Columns** | `surface` (the date as written), `iso` (the answer, always `YYYY-MM-DD`) |
| **Source** | Generated by `make_dates.py` (in this folder). Synthetic. |

A *sequence-to-sequence* task: the input is a sequence of characters and so is
the output.

```text
the 3rd of september , 1993   -> 1993-09-03
2005.03.05                    -> 2005-03-05
saturday , november 8 , 2014  -> 2014-11-08
```

It is a good first sequence-to-sequence task because the answer is
unambiguous (a date is either exactly right or wrong) and because writing
the output means *reordering* the input — the year comes last when written
out but first in `YYYY-MM-DD` — which is what makes attention's behaviour
visible in the lecture's heatmap.

Deterministic given the seeds in the script; rebuild with
`uv run python week-04-sequence-models/data/make_dates.py`.
